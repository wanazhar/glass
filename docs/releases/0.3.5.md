## Major features

- Explicit identity-bound workspace trust gates executable project
  configuration, skills, hooks, tools, tests, LSP, DAP, and experiments.
- Native Pi SDK sessions drive autonomous verified task DAGs with persistent
  sessions, steering, model/thinking control, evidence, and durable reconnect.
- Resident debugger, kernel, experiment, graph/replay, daemon event, and
  desktop/compact/phone TUI contracts converge on one governed tool router.
- Glass Dev directly owns the development project/PTY/runtime core and depends
  one-way on ordinary browser APIs.

## Breaking changes

- The `glass-browser` Cargo feature `development-runtime` is removed. Rust
  applications embedding project, PTY, agent, LSP, or Neovim tooling must
  depend on `glass-dev` and import `glass_dev::development`.
- Shell-backed project tools are always treated as effectively mutating even
  when legacy configuration declared otherwise.

## Security

- Untrusted repositories remain statically inspectable but cannot execute
  repository-controlled configuration or elevate project skills.
- Trust mutation is restricted to explicit local-user surfaces. External
  agents receive read-only trust status/inspection APIs.
- Kernel capability calls retain initiator and executor provenance, enforce
  per-session allowlists, and reject recursive evaluation.

## Installation and migration

Install the complete product with `cargo install glass-dev --locked`, or the
browser-only product with `cargo install glass-browser --locked`. Existing
Rust embedders should replace the removed browser feature with a direct
`glass-dev = "0.3.5"` dependency. Durable stores remain local; opening an
unfamiliar repository starts untrusted until a local trust decision is made.

## Known limitations

- Native Windows named-pipe, LLDB, and Delve claims require their native CI
  jobs on the exact tag; source or Unix-only checks are not certification.
- Persistent kernels govern authority and bounds but are not security
  sandboxes.
- The GitHub tag is not described as verified unless GitHub's tag API reports
  `verification.verified=true`.
- GitHub Releases remain source-only; crates.io is the distribution boundary.

## Validation evidence

The exact tag must pass formatting, warnings-denied Clippy and rustdoc, full
unit/integration/browser smoke tests, real adapter jobs where available,
documentation and schema gates, package verification, publication dry runs,
fuzz/security checks, ordered registry publication, clean installs/upgrades,
and GitHub Release record verification. The workflow binds this body to the
exact tag, commit, and workflow run below.

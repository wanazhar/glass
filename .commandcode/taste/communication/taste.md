# Communication

- Wants to be **interviewed** at the start of a project — asked for structured, option-based questions with the tradeoffs of each made explicit, before any code was written. Do not silently pick defaults on their behalf. The same treatment applies when picking the next milestone ("what can we ship next?") — a ranked set of options with tradeoffs and a stated recommendation, not an open-ended design discussion. Confidence: 0.8
- Frames work as an explicit list of prioritized goals ("1) fast, 2) extendable, 3) lightweight..."). Tie decisions back to those named goals so tradeoffs land. Confidence: 0.7
- Writes tersely and informally (lowercase, no punctuation, blunt phrasing). Match that register; skip preamble and ceremony. Confidence: 0.65
- Wants to be challenged, not managed: welcome to push back on their picks with reasoning and alternatives, but state it once, up front, then proceed. Do not re-litigate a settled decision. Confidence: 0.7
- Tolerates/expects candid reporting of what is unverified or untested; a short honest limitations note at the end is appreciated. Confidence: 0.7

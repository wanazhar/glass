# Revision-guarded navigation task

## Delivered

- `navigation.follow` now executes through a dedicated guarded Task Protocol
  runtime boundary.
- Authored navigation tasks require a bounded `inputs.url` value and retain
  semantic scope and task limits.
- Navigation checks confirmation and source revision before dispatch, then
  returns the verified navigation revision in the shared task result.
- Dispatch errors are reported as indeterminate with unsafe-until-reconciled
  recovery guidance; callers are directed to `recover_run` instead of blind
  replay.
- CLI `glass task execute` and MCP `executeTask` route navigation tasks through
  the same runtime boundary as form and region tasks.

## Verification

- Task Protocol unit coverage rejects navigation tasks without `inputs.url`.
- Linux ARM64 fixture-backed browser smoke executes a guarded navigation task
  before the existing extraction and form task checks.
- Existing form and region extraction behavior remains covered by the same
  full task smoke path.

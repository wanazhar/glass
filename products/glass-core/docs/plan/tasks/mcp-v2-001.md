# Mcp v2

Implementation record. Scope and verification statements describe the recorded checkpoint. See the [current guides](../../INDEX.md) for supported user behavior.

## Objective

MCP revision 2026-07-28 is breaking (stateless core, `server/discover`,
`_meta` on every request, `resultType`, cacheable list results), and remote
MCP servers are where useful servers live. Ship both the revision
negotiation and a Streamable HTTP transport in one pass, so there is one
migration rather than two.

## Context

- **Negotiation**: probe `server/discover` with `_meta` first; on any error
  (method-not-found for older servers) fall back to classic
  `initialize`/`notifications/initialized`. `self.stateless` then governs
  whether every request gets
  `_meta` (`protocolVersion`, `clientCapabilities`, `clientInfo`).
  `resultType: "input_required"` yields a "not supported yet" text;
  `ttlMs`/`cacheScope` are tolerated; missing `resultType` reads as
  `"complete"` per spec.
- **Transports**: `BaseServer` holds the shared call surface; `Server` is
  stdio, `HttpServer` is Streamable HTTP (one POST per request, `Mcp-Method`
  (and `Mcp-Name` for tool calls) headers, JSON or SSE replies, 401 with a
  clear message, HTTPS enforced for non-loopback). `make_server` refuses
  `sse` with a pointer to `streamable-http`.
- Plugin `mcp.json` entries of type `streamable-http` now pass through
  (url/headers deliberately not placeholder-expanded, per spec).
- OAuth v1 = pre-registered client with headers/bearer from config; the full
  CIMD/loopback flow remains out of scope and documented as such.

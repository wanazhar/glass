# Compact persistent MCP and CLI responses

## Objective

Keep the existing lightweight MCP transport while making agent output compact, deterministic, and free of secret-bearing request logs.

## Context

- `docs/architecture/README.md`
- `docs/architecture/browser.md`
- `docs/plan/analysis/performance-overhaul.md`

## Path

- `src/mcp/server.rs`
- `src/cli/args.rs`
- `src/cli/runner.rs`
- `tests/`
- `docs/architecture/browser.md`

## Requirements

- Compact observation is MCP/CLI default; deep DOM and screenshots are opt-in.
- Do not log complete MCP request bodies.
- Preserve the long-lived MCP session model and current lightweight framing.
- Use compact JSON serialization on agent-facing hot paths.
- Expose structured action outcomes consistently across CLI and MCP where practical.

## Verification

- MCP initialize/tools/list/call regression tests.
- CLI parsing/output tests.
- Full fmt, Clippy, and all-target test suite.

## Commit

`perf: compact agent frontend responses`

## Completion

- CLI and MCP observations now serialize compact `PageContext` JSON by default;
  full DOM and screenshot collection are explicit flags.
- CLI/MCP `dom`/`getDOM` perform explicit deep-DOM retrieval, and visible-text
  responses use the compact observation text bound.
- Structured navigation and input-action results use compact JSON consistently.
- MCP parses and validates tool invocations before it creates a persistent
  browser session, so malformed requests do not launch Chrome; it retains the
  existing newline and Content-Length stdio framing.
- MCP logging remains metadata-only and does not include request bodies,
  arguments, or raw request IDs.

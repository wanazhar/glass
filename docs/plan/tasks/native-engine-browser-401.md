# Native worker response-policy ownership (401)

status: done
scope: native-engine/worker-csp-policy-owner
issue: 40

## Objective

Keep the response CSP policy that belongs to an HTTP(S) worker script and make
it available to that worker's asynchronous resource owners. A dedicated or
shared worker must not lose its response `Content-Security-Policy` or
`Content-Security-Policy-Report-Only` declarations when the script crosses the
loader-to-worker boundary.

Slice 400 transported report records into page and worker EventSource
dispatchers, but `load_worker_async` only retained the page-owner policy used
to authorize the worker script. The worker script response headers were not
stored under the resolved worker URL, so later worker connections looked up an
empty policy. This is a policy-ownership gap, not an authorization relaxation.

## Contract

- For a successful HTTP(S) worker script response, store the response CSP
  policy under its final URL after redirects, including all bounded enforced
  and report-only header declarations.
- A worker EventSource, Fetch, and WebSocket operation resolves its policy from
  the worker script URL, while the page policy continues to govern worker
  creation through the existing `worker-src` path.
- A repeated worker load replaces the prior response policy for that URL; a
  response without CSP clears stale policy state rather than inheriting an old
  declaration.
- Policy source bytes stay out of logs, existing limits and fail-closed invalid
  header handling remain unchanged, and report-only policy never authorizes or
  blocks a request.
- Report records generated by the worker loader cross the existing bounded
  EventSource/Fetch/WebSocket owner boundary exactly once and are dispatched
  in the worker realm before the triggering resource event is observed.

## Non-goals

This slice does not add a complete CSP source-expression grammar, dynamic
policy-container mutation, network `report-uri`/`report-to` delivery, or
policy inheritance for every nested worker/module graph edge. Service Worker
response-policy propagation and full worker policy-container conformance remain
separate issue #40 work.

## Implementation path

- Store the final HTTP(S) worker-script response policy in the shared native
  loader after body/type validation.
- Reuse the existing EventSource transport record path and structured worker
  `SecurityPolicyViolationEvent` dispatcher.
- Add an HTTP(S) dedicated-worker EventSource report-only witness and retain the
  existing worker transport regressions.
- Update architecture, plan, analysis, and this task with exact evidence.

## Delivered

- Successful HTTP(S) worker-script responses now store enforced and report-only
  CSP under the final resolved worker URL, replacing any previous entry.
- Dedicated and shared worker EventSource, Fetch, and WebSocket owners can
  reuse that response policy through the existing native loader boundary.
- Added a content-process witness proving a worker EventSource receives its
  report-only `connect-src` event before the worker forwards the message.
- Page worker creation remains governed by the page policy and no report-only
  record changes authorization.

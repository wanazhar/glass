# Continuation contract binding

## Objective

Prevent a continuation token from being reused with a different extraction
field contract on the same page and region.

## Contract

- Continuation metadata carries a non-sensitive SHA-256 fingerprint of the
  requested fields and region scope.
- Resumed extraction must use the same field order, names, paths, kinds, and
  region scope as the original slice.
- A mismatched contract fails closed before extraction output is produced.
- Input values and page content are never included in the fingerprint.

## Delivered

- Added deterministic extraction contract hashing to continuation metadata.
- Validated the hash alongside source revision, route, and region.
- Extended MCP schema, documentation, and focused continuation coverage.

## Verification

- Continuation and MCP-focused tests pass.
- Full Rust, formatting, check, Clippy, documentation, and browser smoke checks
  remain required before the next release boundary.

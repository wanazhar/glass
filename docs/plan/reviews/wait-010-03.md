# Final audit: wait-010 typed browser waits

Reviewed branch through `7fe929e` (`fix: serialize network wait transitions`).

Conclusion: **blocked**. Ordinary lease transitions are now serialized and
visible-text filtering is materially corrected. Cancellation or failure during
the final disable can still double-release lease ownership and disable a new
wait.

## Finding

### P1 — blocking: cancelled/failed final disable double-releases the lease

`NetworkDomainGuard::disable` calls `release_network_lease(...).await?` and
clears `armed` only after that function succeeds
(`src/browser/session.rs:1519-1524`). `release_network_lease` decrements the
count to zero while holding the mutex and then awaits `Network.disable` under
the same lock (`src/browser/session.rs:1540-1551`).

If that await is cancelled or returns an error after the count was decremented,
the guard remains armed. Its `Drop` schedules another
`release_network_lease`. Once the first future releases the mutex, a new wait
may acquire, increment to one, and successfully enable Network. The stale drop
cleanup then acquires the lock, decrements the *new* lease to zero, and disables
Network beneath the active waiter. Without a new waiter, the saturating second
decrement still issues a redundant disable.

Lease ownership must be consumed exactly once independently of whether the CDP
disable acknowledgement succeeds. Mark/disarm the guard before entering the
final release transition, or give each guard an ownership token that the state
machine removes once. Domain state may need a `disable_pending/unknown` state
so a new acquisition waits for the old command and re-enables deterministically
after failure. Add forced cancellation and forced CDP error during
`Network.disable`, each followed immediately by a new acquisition.

The added cancellation test drops one wait while another lease is already
active (`tests/browser_smoke.rs:797-812`), so the shared count never reaches
zero during cancellation and does not exercise this final-disable path.

## Resolved wait-010-02 findings

- The mutex is held across first `Network.enable` and final `Network.disable`,
  preventing ordinary acquire/release command reordering
  (`src/browser/session.rs:1498-1517`, `1540-1551`). Enable failure explicitly
  rolls count back before unlocking. The blocker above is the remaining
  cancellation/error ownership edge.
- Directly constructed `WaitCondition` values now pass `condition.validate()`
  at `BrowserSession::wait`, enforcing 1–4096-byte strings and bounded nonzero
  network quiet durations at the library boundary
  (`src/browser/session.rs:854-868`, `1639-1667`).
- Navigation carries the original caller deadline separately from its remaining
  lifecycle sub-budget, so timeout diagnostics report the original value
  (`src/browser/session.rs:653-678`, `870-897`).
- Visible-text polling now traverses text nodes and rejects hidden,
  opacity-zero, zero-area, and fully clipped ancestor chains
  (`src/browser/session.rs:1819-1850`). Real-browser checks prove the opacity
  and clipping fixtures do not satisfy the wait
  (`tests/browser_smoke.rs:856-872`). No regression to untruncated substring
  semantics was found.
- Lag and overflow remain conservative: neither can produce a false quiet
  success. Lag/closed-domain errors are still generic MCP failures rather than
  typed bounded wait failures (`src/browser/session.rs:1074-1075`); this remains
  a non-blocking diagnostic improvement.

## Remaining non-blocking follow-ups

- Visible substring matching is per text node. A phrase split across adjacent
  inline nodes will not match even if it appears contiguous when rendered.
  Define and test whether page-visible substring semantics should span nodes.
- Network transition/lag/overflow tests and expensive-path resource evidence
  remain incomplete. The completion still records only cheap `js=true`
  latency, binary/context size, and post-workload RSS
  (`docs/plan/tasks/wait-010.md:78-82`).

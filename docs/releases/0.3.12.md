# Glass 0.3.12

Status: Published immutable release record for tagged `v0.3.12` (2026-08-22).
It describes the exact release contents; post-tag current-source work is
tracked under [Unreleased](../../CHANGELOG.md#unreleased).

Glass 0.3.12 packages the Pi runtime integration and the responsive Glass Dev
TUI workflow as one complete development surface. The Agent surface can set up,
authenticate, update, and converse with the managed Pi runtime without leaving
the TUI, while browser recovery and target selection remain governed and
responsive.

## Major features

- In-TUI Pi onboarding configures the shared workspace, reports runtime
  readiness, and exposes setup, login, update, and new-conversation actions
  from the Agent surface and command palette.
- The resident Pi runtime is pinned to the verified `0.84.2` SDK surface and
  uses bounded session workers, evidence events, retryable composer turns, and
  explicit failure recovery.
- Glass Dev adds consistent responsive panels, action details, status colors,
  quick-key rails, a first-step Agent landing card, and readable desktop,
  compact, and mobile layouts.
- Browser start and navigation keep the TUI responsive while headed persistent
  profiles, target selection, redacted page inventory, and port-collision
  recovery make the browser path usable from the same workspace.
- `glass archive-targets` exports a bounded, redacted page-target inventory for
  review without exposing cookies, page secrets, or evaluated user input.
- The release package and client metadata now expose the matching 0.3.12
  source line, including discoverable `glass-dev` docs.rs API documentation.

## Breaking changes

There are no intentional Rust, CLI, MCP, profile, or workspace-storage
removals. The package boundary remains one-way: `glass-dev` depends on the
exact matching `glass-browser` release. Existing resident-agent callers should
continue to use the negotiated `glass.*` catalog and bounded session controls.

## Security

Browser mutations remain revision-bound and fail closed on stale target state.
Workspace trust, actor authority, confirmation, mutation leases, bounded
queues, and explicit human takeover continue to gate privileged operations.
The Pi runtime remains a Glass-owned gateway: provider credentials and prompt
content are not logged, browser policy is not bypassed, and tool evidence is
bounded and attributed to the selected workspace and agent session.

## Installation and migration

Install the complete product with:

```console
cargo install glass-dev --version 0.3.12 --locked --force
```

Library users select:

```toml
glass-browser = "0.3.12"
```

The full package retains the exact `glass-browser =0.3.12` dependency. Follow
the [0.3.12 migration guide](../migration/0.3.12.md) when upgrading from the
0.3.11 line. Start `glass` in a trusted project; the Agent surface presents
runtime setup and authentication actions when Pi is not ready.

## Known limitations

- Chrome/Chromium remains the only automation backend.
- Native browser, graphics, PTY, and debugger certification is
  platform-specific.
- Remote View deliberately requires loopback or SSH forwarding.
- TypeScript and Python clients remain repository clients; this release has no
  npm or PyPI artifacts.
- Provider login still depends on the selected Pi provider and its local
  authentication requirements.

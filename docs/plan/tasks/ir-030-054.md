issue: 30
release: 0.2.5
status: complete

## Objective

Make Web IR revision comparisons fail closed when a caller supplies a stale or
inconsistent dynamic-page revision.

## Contract

- A forward revision may be compared for diff and continuity analysis.
- An exact same-revision draft may be compared with itself for deterministic
  offline projections.
- A revision regression is rejected with a bounded `revision` validation path.
- Same-revision content drift is rejected with a bounded `revision` validation
  path.
- Canonical `webIr.diff` and `webIr.continuity` payload validation applies the
  same transition rules before dispatch.
- Ambiguous semantic rebinding remains an explicit continuity classification
  with no current entity ID.

## Evidence

- Web IR unit tests cover stale reverse diffs, same-revision content drift,
  forward changed revisions, rebound entities, removed entities, and ambiguous
  continuity.
- `tests/fixtures/web-ir/revision-cases-v1.json` records compatible, stale, and
  ambiguous contract cases.
- Canonical protocol conformance remains passing for Web IR diff and continuity
  requests.
- Full 0.2.5 release validation, Linux ARM64 browser smoke, package dry-run,
  and clean install upgrade smoke passed locally.

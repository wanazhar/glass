# ir-030-040

Status: complete

## Objective

Expose browser-free Task Protocol validation and compilation through canonical
Glass operation names shared by MCP and embedded Rust callers.

## Contract

- `task.validate` carries one strict authored `GlassTask` under `task` and
  returns bounded `TaskValidationResult` metadata.
- `task.compile` carries the same strict authored task and returns a typed,
  deterministic `TaskCompileResult`.
- MCP `validateTask` and `compileTask` map to these operations before browser
  startup, target resolution, or mutation lease acquisition.
- Unknown fields, invalid authored tasks, and mismatched operation payloads are
  rejected before compilation or execution.

## Evidence

- Canonical request and response helpers are implemented in `glass::protocol`.
- MCP canonical mapping coverage exercises both Task Protocol tools.
- Protocol golden coverage includes both task operation envelopes.
- Focused protocol and MCP tests pass; full repository checks remain the
  release gate.

# ir-030-041

Status: complete

## Objective

Ensure MCP Task Protocol tools execute through the canonical Glass protocol
boundary rather than duplicating task validation and compilation logic.

## Contract

- `validateTask` constructs a canonical `task.validate` request and uses the
  typed protocol validation helper.
- `compileTask` constructs a canonical `task.compile` request and uses the
  typed protocol compilation helper.
- MCP-only transport options such as `responseMode` and `includeTrace` are not
  included in the canonical task payload.
- Browser startup, target resolution, and mutation lease acquisition remain
  bypassed for both operations.

## Evidence

- MCP dispatch tests cover successful validation and compilation with no browser
  session.
- Canonical boundary coverage proves transport options are excluded and typed
  request decoding succeeds.
- Full repository validation remains the release gate.

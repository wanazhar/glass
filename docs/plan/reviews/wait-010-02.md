# Re-review: wait-010 typed browser waits

Reviewed branch through `bddead9` (`fix: enforce wait deadlines and network
leases`).

Conclusion: **blocked**. Overall deadline enforcement, navigation integration,
bounded public inputs, conservative lag/overflow behavior, and condition
coverage are improved. The Network lease implementation still has command-
ordering races, and “visible text” still includes visually hidden content.

## Findings

### P1 — blocking: lease count transitions are not atomic with Network domain transitions

`NetworkDomainGuard::acquire` increments the shared count under the mutex,
releases the mutex, and only then awaits `Network.enable`
(`src/browser/session.rs:1494-1510`). A concurrent second acquisition sees a
nonzero count, skips enable, and begins its quiet clock while the first enable
is still pending. If the first enable fails or is cancelled, the second waiter
continues under the false assumption that Network is active.

Release has the inverse race. `release_network_lease` decrements to zero under
the mutex, unlocks, and then awaits `Network.disable`
(`src/browser/session.rs:1533-1542`). A new acquisition can increment from zero
and enqueue `Network.enable` before the old release enqueues its disable; CDP
can then process enable followed by disable, leaving the new active lease with
Network off. The asynchronous drop cleanup makes this cancel-then-reacquire
ordering particularly plausible.

Use a mutex-protected state machine (`Disabled`, `Enabling`, `Enabled(n)`,
`Disabling`) or hold serialized transition ownership until the CDP command
completes. Failed/cancelled enable must roll back before another lease can
proceed, and acquisition during disable must wait then re-enable in order. Add
deterministic delayed-enable/disable, failed-enable, overlapping completion,
and cancel-then-immediate-reacquire tests. The current happy-path `join!` test
does not force either transition race (`tests/browser_smoke.rs:783-799`).

### P2 — blocking: visible-text wait still matches invisible content

The wait now avoids the 16 KiB compact-text truncation and docs consistently
define substring semantics. However, it evaluates
`document.body.innerText.includes(...)` (`src/browser/session.rs:935-944`).
`innerText` includes text under `opacity: 0` and can include fully clipped text,
so a condition documented as `text=<visible substring>` can succeed when no
text is visually present. This repeats the ancestor-opacity/clipping issue
already fixed for deterministic `text=` targeting.

Reuse the bounded rendered-visibility semantics from the text locator, or
rename/document this as layout text rather than visible text. Add opacity-zero,
clipped, and visible duplicate tests. The current delayed-text test covers only
ordinary visible content.

### P2 — non-blocking: direct typed callers bypass condition and quiet bounds

The 4 KiB limit is enforced only by `WaitCondition::parse`; `BrowserSession::wait`
accepts the public enum directly without validating string variant sizes
(`src/browser/session.rs:854-867`, `1576-1620`). Library callers can construct a
multi-megabyte JavaScript/text/target/URL condition. Likewise, a directly
constructed `NetworkQuiet` duration greater than 300 seconds is not rejected
(only zero is checked at `src/browser/session.rs:1017-1019`). The overall
deadline remains bounded, but the retained field and semantic quiet-duration
bounds should apply at the session API boundary, not only CLI/MCP parsing.

### P2 — non-blocking: navigation timeout diagnostics report the remaining sub-deadline

Navigation correctly wraps `Page.navigate`, lifecycle checking, and page-info
inside one elapsed budget (`src/browser/session.rs:653-678`). It passes the
remaining duration into `wait_loop`, whose timeout reports that remaining value
as `deadline_ms`, not the caller's original deadline
(`src/browser/session.rs:665-672`, `870-894`). If navigation consumes most of a
20-second budget, the resulting diagnostic can claim a much smaller deadline
or even zero. Carry the original deadline separately from the remaining
timeout so MCP/CLI evidence reflects the caller contract.

### P2 — non-blocking: lag and Network transition errors lose typed timeout evidence

Event lag/closure now fail conservatively, which fixes false success, but return
generic string errors (`src/browser/session.rs:1075-1076`). Enable/disable and
other condition errors are also generic. MCP consequently returns `browser tool
failed`, not the condition/deadline/bounded last state promised for wait
diagnostics. Introduce a bounded typed wait failure kind for event loss/domain
transition errors, distinct from deadline timeout.

### P3 — non-blocking: network adversary and resource evidence remain incomplete

The real-browser matrix now covers every condition variant, overlapping happy-
path leases, never-idle traffic, and a pending JavaScript deadline
(`tests/browser_smoke.rs:768-889`). It does not force broadcast lag, 1,024-ID
overflow, pre-activation traffic semantics, transition failures, cancellation
during enable/disable, or immediate reacquisition. The completion also retains
only the cheap `js=true` latency plus binary/context/post-workload RSS
(`docs/plan/tasks/wait-010.md:73-77`); it does not report Network event payload,
peak RSS, CDP round trips, or cancellation/lease overhead. Those should be
recorded for the explicitly expensive Network path.

## Resolved wait-010-01 findings

- Every semantic check is wrapped in the remaining deadline; the real-browser
  never-resolving Promise returns a `WaitTimeout` within the short bound
  (`src/browser/session.rs:870-915`, `tests/browser_smoke.rs:878-889`). Public
  parser/MCP deadlines are limited to 1–300,000 ms and condition strings to
  4 KiB (`src/browser/session.rs:1576-1649`; `src/mcp/server.rs:785-794`).
- Network event lag now fails conservatively and overflow becomes a permanent
  conservative state instead of guessing request identity
  (`src/browser/session.rs:1027-1077`).
- Pre-activation requests are no longer claimed as observable: the architecture
  and completion explicitly define observation from first lease activation
  onward (`docs/architecture/browser.md:98-104`,
  `docs/plan/tasks/wait-010.md:56-60`).
- Navigation exposes a bounded deadline through library, CLI, and MCP,
  subscribes before `Page.navigate`, and shares `wait_loop` lifecycle polling
  and event state (`src/browser/session.rs:648-678`; `src/cli/args.rs:71-78`;
  `src/mcp/server.rs:519-524`, `594-600`).
- Text semantics and docs now consistently say untruncated substring rather
  than exact compact text (`docs/architecture/browser.md:88-99`,
  `src/browser/session.rs:935-944`). The visual-visibility blocker above remains.
- Real-Chrome success coverage now includes lifecycle, exact/prefix URL,
  attached/visible/hidden/enabled/stable targets, text, JavaScript, network,
  redirect, timeout, and cancellation variants (`tests/browser_smoke.rs:768-889`).

# Migrate from 0.3.4 to 0.3.5

Glass 0.3.5 hardens repository trust and completes ownership of the resident
development runtime. Existing browser automation remains structured-first;
screenshots and full DOM capture remain explicit operations.

## Installation

Update the complete product with:

```console
cargo install glass-dev --version 0.3.5 --locked --force
```

Install `glass-browser` separately only for the browser-only CLI/library. The
GitHub Release remains source-only and does not contain native binaries.

## Rust dependency change

The `glass-browser/development-runtime` feature no longer exists. Replace:

```toml
glass = { package = "glass-browser", version = "0.3.4", features = ["development-runtime"] }
```

with:

```toml
glass-dev = "0.3.5"
```

and replace `glass_browser::development` imports with
`glass_dev::development`. Browser-only consumers keep their ordinary
`glass-browser` dependency without features.

## Workspace trust

Repositories containing executable Glass configuration now open untrusted
unless their exact identity is already in the local trust store. Static files
and configuration inspection remain available. Project hooks, tools, skills,
tests, LSP, DAP, experiments, and commands do not execute until a local human
chooses trust-once or persistent project trust. `--yolo` does not bypass this
boundary.

Review unfamiliar repositories on the Trust surface. Persistent decisions are
identity-bound; moving or replacing a repository requires a fresh decision.

## Customization authority

User-global skills and trusted project skills are distinct authority classes.
Project content cannot declare itself trusted. Shell-backed project tools are
effectively mutating regardless of a legacy `mutating=false` declaration and
therefore require mutation authority and confirmation.

## Tasks, agents, and sessions

A Pi session is conversational state, an agent is an executing worker, and a
task is a durable schedulable unit with dependencies, budgets, verification,
retry, and evidence. Task creation automatically dispatches ready work; do not
send a second manual prompt merely to start it. Agent settlement is not task
success until verification passes.

External agents can call `glass.task.*` and read-only
`glass.workspace.trust.*` APIs directly through CLI/MCP/daemon routing without
nesting through Pi.

## Durable runtime and reconnect

The local daemon retains complete workspace identity and resident resources
across client disconnects. Clients may resume the bounded `workspace.events`
cursor and must handle `lostBefore`/`droppedEvents` explicitly. Unix uses a
local socket; Windows uses a local named pipe, with native certification shown
only when the exact-tag Windows job passes.

## Debuggers, kernels, and experiments

Debugger support is adapter-neutral, but only adapters with exact-tag real
tests are certified. Check the debugpy/LLDB/Delve matrix before relying on a
platform claim. Persistent Python, JavaScript, shell, and SQL kernels can call
allowlisted Glass tools with dual provenance; they are governed runtimes, not
security sandboxes. Experiment ranking distinguishes measured, unavailable,
and manually supplied evidence.

## TUI changes

Trust, Agent, Tasks, Editor, LSP, Processes, Browser, Workflow, Debugger, Git,
Tests, Kernels, Experiments, Graph, Replay, and Daemon/Workspace are direct
surfaces. Compact and phone layouts use drill-down and prioritize workspace,
task, agent, semantic/browser, health, recovery, and trust decisions.

## Rollback

Before rollback, stop `glass daemon` so the older binary does not attach to a
newer resident actor. Keep a copy of local `.glass` state and trust data. Do
not reuse a newer daemon process with an older CLI; stop it and restart the
matching version.

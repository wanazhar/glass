# Responsive worker-based terminal UI

## Objective

Keep the current layout while moving browser I/O out of the TUI input/render loop.

## Context

- `docs/architecture/README.md`
- `docs/architecture/browser.md`
- `docs/architecture/tui.md`
- `docs/plan/analysis/performance-overhaul.md`

## Path

- `src/tui/`
- `src/browser/session.rs` (only if a worker-facing API is necessary)
- `tests/`
- `docs/architecture/tui.md`

## Requirements

- Retain the current header, two panels, command input, and footer layout.
- Introduce typed browser command/event channels using existing Tokio/Crossterm facilities.
- Browser I/O must not block rendering or key processing.
- Keep UI page state bounded and compact; no base64 screenshot cache.
- Add busy, error, shutdown, and cancellation state handling.
- Guarantee terminal restoration on all normal error/exit paths.

## Verification

- Reducer/command parsing unit tests.
- Worker event test proving a delayed command does not prevent UI key/event handling.
- Full fmt, Clippy, and all-target test suite.

# Bounded extraction continuation

## Objective

Make truncated table and repeated-item extraction resumable without allowing
an unbounded autonomous loop or mixing evidence from different page states.

## Contract

- Requests may provide a bounded `startIndex`; omitted values default to zero.
- Array fields are sliced to `startIndex..startIndex + maxItems`.
- `recordItems.index` remains the source-array index across slices.
- Results include `continuation` only when more items remain.
- Continuation metadata carries the next source index, source revision, and
  source route; callers must preserve those values before requesting another
  slice.
- Existing `records`, provenance, limits, and fallback behavior remain
  compatible; scalar and object fields are not paginated.

## Delivered

- Added `startIndex` to the Rust extraction request and MCP schema.
- Added revision-bound continuation metadata to extraction results.
- Added source-index preservation and schema regression coverage.

## Verification

- Focused extraction, task, and MCP tests pass.
- Full Rust, formatting, check, Clippy, documentation, and browser smoke checks
  remain required before the next release boundary.

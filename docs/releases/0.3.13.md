# Glass 0.3.13

Status: Release record for version `0.3.13`, dated 2026-08-27.

Glass 0.3.13 brings the complete Glass Dev workspace into the coding loop:
the Agent surface, editor, browser presentation, and governed Pi runtime are
available as one coherent TUI workflow. The release keeps browser automation
explicit while making repository work, review, and resident-agent activity
visible together.

## Major features

- The Code surface now renders source and diffs with path-aware syntax
  highlighting, including Markdown fences and Mermaid source, with aliases for
  common TypeScript, Swift, Kotlin, Dart, and Dockerfile-like paths. A
  deterministic manual/plain-text path remains available when highlighting is
  unavailable, and diff additions/removals retain distinct backgrounds.
- Editor collaboration is actor-attributed and reviewable. Durable line
  comments can be resolved, replacement proposals retain their base content
  and revision, and proposals expose pending, accepted, rejected, and stale
  states. Named in-memory checkpoints make a buffer state available for
  deliberate review and recovery.
- The complete `glass` entry point presents trust, readiness, Pi setup/login,
  the composer, files, PTYs, tests, LSP, Git, tasks, and browser controls from
  the TUI. `:actions`, surface command menus, `glass harness`, and governed
  delegation provide discoverable routes without requiring a separate daemon
  bootstrap.
- The Agent landing surface is organized around a coding workspace: repository
  changes and checks sit beside the conversation, with the browser app shown as
  an explicit development surface rather than an implicit default.
- Live browser presentation supports Kitty terminal graphics alongside Herdr
  and ANSI half-block output. `--tui-live` is opt-in, backend selection is
  explicit (`auto`, `herdr`, `kitty`, or `ansi`), quality profiles are bounded,
  and semantic output remains available when live pixels cannot be used.
- The managed native Pi runtime is aligned to SDK `0.84.3`. Readiness,
  setup/update, resident-session selection, retryable turns, and governed tool
  execution remain available from the TUI and CLI without silently choosing an
  upstream SDK version.
- Wrapped editor rows, selections, and cursor positions stay synchronized with
  the source viewport. Long lines preserve syntax and selection styling, and
  the visual cursor remains correct through wrapping, including at end of line.

## Breaking changes

There are no intentional Rust, CLI, MCP, or workspace-storage removals. The
package boundary remains one-way: `glass-dev` is the complete product and uses
an exact matching `glass-browser` dependency, while `glass-browser` remains the
focused browser product and embeddable crate.

The primary workflow change is presentational: the Agent surface is now a
coding-workspace landing surface and browser automation is an explicit App
surface. Operators who previously treated browser controls as the implicit
entry point should open App or use the browser commands explicitly. The live
pixel path is also opt-in; semantic output is the compatibility path when a
terminal does not provide supported graphics.

## Security

Editor comments, proposals, and checkpoints retain actor attribution and
revision context. A proposal based on an older buffer becomes stale instead of
overwriting a changed buffer. Browser mutations continue to require governed
workspace state, authority, leases, confirmation, and a matching semantic
revision; stale targets fail closed.

The native Pi runtime routes tools through the Glass workspace authority
boundary. Provider credentials and prompt content are not written to release
notes or tool evidence, browser URLs are redacted in evidence, and bounded
queues, frame sizes, timeouts, and result limits remain in force. Explicit
unrestricted mode does not remove path, revision, lease, protocol, or resource
bounds.

## Installation and migration

Install the complete product with the exact release version:

```console
cargo install glass-dev --version 0.3.13 --locked --force
```

The focused browser-only product is an alternative package owner:

```console
cargo uninstall glass-dev
cargo install glass-browser --version 0.3.13 --locked --force
```

Library users select the matching browser crate:

```toml
glass-browser = "0.3.13"
```

Choose one package owner for a Cargo home because both products provide a
`glass-browser` executable. The full product carries the exact
`glass-browser =0.3.13` dependency. For the behavioral and operational steps,
see [Migrate from 0.3.12 to 0.3.13](../migration/0.3.13.md).

## Known limitations

- Chrome/Chromium remains the supported automation backend; live graphics
  depend on the selected terminal backend and its capabilities.
- Native browser, graphics, PTY, debugger, and Pi behavior remains bounded by
  platform-specific support and the evidence scope recorded for the release.
- Remote View remains intended for loopback or SSH-forwarded operation.
- TypeScript and Python clients remain repository clients; this release does
  not create npm or PyPI artifacts.
- Pi provider authentication still depends on the selected provider and its
  local credentials. Glass does not impersonate a provider.
- Existing Pi session files may be empty, outside the selected session
  directory, or incompatible with the selected SDK; Glass rejects those cases
  rather than silently rewriting them.

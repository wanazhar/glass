# Typed structured extraction provenance and limits

## Objective

Advance the 0.2.8 native structured-extraction slice by making the existing
browser-free extraction contract express the bounded scalar types required by
Issue #30 and return auditable field-level provenance and limit metadata.

## Contract

- Extraction remains read-only and uses the existing semantic observation path.
- Authored fields contain semantic names and bounded paths, never selectors,
  XPath, CDP node IDs, or page values.
- Existing extraction kinds remain compatible; new kinds reject incompatible
  values before a result is returned.
- Result provenance includes source revision, optional region scope, and
  evidence-backed semantic entity references when a scoped region supplies them.
- Limits report requested bounds, observed item counts, serialized output bytes,
  and truncation explicitly.
- Sensitive values remain governed by existing semantic observation policy.

## Delivered

- Added explicit `string`, `optionalString`, `number`, `currency`, `date`,
  `dateTime`, `boolean`, `url`, `enum`, `list`, `record`, `table`, and
  `repeatedItems` extraction kinds while retaining legacy kinds.
- Added bounded `fieldProvenance` entries with field paths, optional region
  scope, and semantic entity references discovered from extracted targets.
- Added `limits` metadata for requested item/byte bounds, observed items,
  serialized output size, and truncation.
- Extended the MCP `extractStructured` schema and documentation with the typed
  field contract.

## Verification

- Unit tests cover every new value kind, invalid values, field provenance, and
  item/byte limit metadata.
- The MCP `extractStructured` schema and documentation expose the typed field
  contract without exposing input values; the CLI consumes the same typed Rust
  request contract.
- `cargo fmt`, focused extraction/task/MCP tests, full `cargo test
  --all-targets --locked`, `cargo check --locked`, and Clippy with warnings
  denied passed.

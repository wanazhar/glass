# Glass 0.3.14

Status: Release record for version `0.3.14`, dated 2026-08-29.

Glass 0.3.14 makes the resident development workspace a complete coding loop:
the composer, modal editor, project workbenches, governed Git operations,
resident Pi sessions, and bounded overnight crew evidence are available beside
the browser control plane. The release keeps every mutation tied to workspace
trust, actor authority, revisions, leases, and explicit confirmation.

## Major features

- The resident Agent surface now has a shared composer with Ask, Plan, and
  Agent modes. It keeps conversation, repository state, tests, diagnostics,
  browser evidence, and session controls in one TUI workflow. Ask and Plan
  remain read-only for mutations; Agent writes through reviewable proposals
  and a prove-it verification path.
- The Code surface now provides a modal editor with Normal, Insert, Select, and
  Agent modes; structural motions, operators, text objects, multi-cursor
  ranges, soft wrapping, syntax-aware diffs, and cursor synchronization. The
  parser uses incremental tree-sitter updates with a lexical fallback.
- Local and resident fill-in-the-middle ghosts, pair-apply review, editor
  comments, replacement proposals, checkpoints, LSP diagnostics/inlays, and
  source-to-live-app jumps are connected to the current buffer revision.
- Git, Debug, Terminal, Tasks, and More are distinct workbenches with shared
  action menus, mouse paths, responsive desktop/phone layouts, and explicit
  routes. Governed Git now covers fetch, pull, merge, rebase, stage, unstage,
  discard, push, branches, stashes, and worktrees.
- The task surface can queue a bounded overnight crew of architect,
  implementer/tester, reviewer, and browser-verification work. Crew members
  use isolated `.glass/worktrees` paths; the durable wake pack in
  `.glass/crew/` folds their states, diffs, tests, verification, and review
  evidence back into a human-controlled proposal pack.
- The managed resident Pi AgentSession path now exposes session setup,
  readiness, model state, follow-ups, branching, rewind, compaction, steering,
  and governed tool approval from the TUI and MCP service. The full-product
  source inventory contains 344 negotiated tools, including the workspace
  checklist and complete Git verb set.

## Breaking changes

There are no intentional Rust, CLI, MCP, or workspace-storage removals. The
package boundary remains one-way: `glass-dev` is the complete product and uses
an exact matching `glass-browser` dependency, while `glass-browser` remains
the focused browser product and embeddable crate.

The default resident Agent workflow is proposal-oriented. Ask and Plan cannot
perform mutations, and Agent changes should be reviewed and proved before they
are accepted. Operators who previously treated a direct editor or browser
action as the primary route should use the Code/App workbench and its action
menu so the active revision, authority, and confirmation state remain visible.

## Security

Workspace files, Git operations, PTYs, LSP actions, editor proposals, browser
mutations, and resident-agent tools retain path, trust, actor, revision, lease,
confirmation, frame, timeout, and result bounds. A proposal based on an old
buffer becomes stale instead of overwriting a newer revision. Crew worktrees
are confined below `.glass/worktrees`, and wake records contain bounded
evidence rather than provider credentials or prompt content.

Browser policy interception covers every Fetch resource type, including worker
and non-document requests. CDP connections, daemon children, and client frame
parsers fail closed on timeouts, malformed frames, incomplete bodies, policy
denials, and tool errors. Browser URLs and sensitive outputs remain redacted in
release evidence.

## Installation and migration

Install the complete product with the exact release version:

```console
cargo install glass-dev --version 0.3.14 --locked --force
```

The focused browser-only product is an alternative package owner:

```console
cargo uninstall glass-dev
cargo install glass-browser --version 0.3.14 --locked --force
```

Library users select the matching browser crate:

```toml
glass-browser = "0.3.14"
```

Choose one package owner for a Cargo home because both products provide a
`glass-browser` executable. The full product carries the exact
`glass-browser =0.3.14` dependency. Follow [Migrate from 0.3.13 to
0.3.14](../migration/0.3.14.md) for the editor, composer, crew, Git, client,
and rollback steps.

## Known limitations

- Chrome/Chromium remains the supported automation backend; live graphics
  depend on the selected terminal backend and its capabilities.
- Native browser, graphics, PTY, debugger, and Pi behavior remains bounded by
  platform-specific support and the exact evidence scope recorded for the
  release.
- Remote View remains intended for loopback or SSH-forwarded operation.
- TypeScript and Python clients remain repository clients; this release does
  not create npm or PyPI artifacts.
- Pi provider authentication still depends on the selected provider and its
  local credentials. Glass does not impersonate a provider.
- Existing Pi session files may be empty, outside the selected session
  directory, or incompatible with the selected SDK; Glass rejects those cases
  rather than silently rewriting them.

# ir-030-053

Status: complete

## Objective

Harden the browser-free Task Protocol execution-plan boundary before a plan is
handed to a runtime.

## Contract

- Plans validate their scope and bounded execution limits independently of the
authored task.
- Plans begin with exactly one non-confirmed scope observation and contain the
exact operation selected by their task kind.
- Plan step count cannot exceed `maxActions`.
- Fill steps carry unique, bounded input names; other operations carry none.
- Risk and ambiguity metadata cannot silently remove required confirmation.
- Existing canonical plan output remains deterministic and excludes input
  values.
- Plan postconditions reuse the Task Protocol count and expectation bounds.

## Evidence

- Compiler regression tests cover action-budget overflow, operation mismatch,
empty fill inputs, and missing risky-task confirmation metadata.
- Existing task compiler tests continue to cover stable operation ordering,
confirmation propagation, and canonical value omission.
- Regression tests also cover unbounded postconditions and fill-input counts.

# Sensitive extraction guard

## Objective

Prevent accidental extraction of credentials and other secret-like fields from
semantic page evidence.

## Contract

- Field names and paths containing bounded secret indicators are sensitive.
- Sensitive extraction requires the explicit `read_sensitive_form_values`
  capability already used for sensitive form-value access.
- Without that explicit capability, extraction fails before semantic output is
  collected.
- Detection is conservative and never inspects or logs extracted values.
- Non-sensitive extraction remains unchanged.

## Delivered

- Added bounded sensitive-name and path detection for structured extraction.
- Added fail-closed policy gating and focused detection coverage.
- Documented the policy requirement in the MCP extraction contract.

## Verification

- Sensitive-field detection and extraction-focused tests pass.
- Full Rust, formatting, check, Clippy, documentation, and browser smoke checks
  remain required before the next release boundary.

# Lsp

Implementation record. Scope and verification statements describe the recorded checkpoint. See the [current guides](../../INDEX.md) for supported user behavior.

## Objective

LSP diagnostics (OpenCode is a reference implementation; Copilot CLI packages `lsp.json`;
Claude Code's 60s per-server timeout is the failure mode to avoid). The
compiler's verdict belongs in the tool result the model reads, not in a
side channel it has to ask for.

## Context

- `extensions/lsp`: stdio LSP framing, initialize handshake, didOpen /
  didChange (full-text, versioned), publishDiagnostics collection with a
  quiet-period debounce, `shutdown` + `exit` on goodbye. Servers start
  lazily per language, stay warm for the session, and a server that cannot
  start is reported once, then ignored — a missing language server must
  never break the edit loop.
- Hook: `tool_result` for bash; the newest `[wrote …]` path in the body
  that has a configured language is checked; diagnostics append as
  `[lsp] path:line:col severity: message` with the original body preserved.
- **Core change**: `rewrite_tool_result`'s wait budget went from 5s to 50s
  (`REQUEST_TIMEOUT_MS * 10`). A cold language server legitimately takes
  seconds, and the 5s window would silently discard the rewrite — the same
  late-reply class of bug auto-verify hit from the other side.
- Explicit `lsp {path}` tool (warm-up / re-check) and `/lsp` status command.

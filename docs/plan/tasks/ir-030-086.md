# Continuation source validation

## Objective

Prevent a resumed extraction request from combining a prior page slice with a
new semantic observation.

## Contract

- A continuation object returned by `extractStructured` may be sent back in a
  subsequent request.
- Glass validates its source revision and route against the fresh semantic
  observation before extracting any values.
- Mismatched source metadata fails closed with a bounded request error.
- `startIndex`, when supplied with a continuation, must be zero or equal to
  the continuation's `nextIndex`.
- Direct bounded extraction without a continuation remains compatible.

## Delivered

- Made continuation metadata deserializable as a request token.
- Added revision and route validation before region selection and extraction.
- Extended the MCP input schema and focused validation coverage.

## Verification

- Continuation and MCP-focused tests pass.
- Full Rust, formatting, check, Clippy, documentation, and browser smoke checks
  remain required before the next release boundary.

# Glass 0.3.6

Glass 0.3.6 is an urgent product repair centered on a single canonical Browser
Workspace and a rebuilt Agent-first desktop/phone experience.

This exact-tag release is retained as historical audit evidence. Current users
should install 0.3.12; the 0.3.6 package was not a public registry release.

## Major features

- The standalone Browser TUI and embedded App surface share the same bounded,
  revision-safe state/action/capability controller.
- Structured accessibility observation remains the default. Visual output is
  explicit through screenshots, Herdr latest-frame presentation, or tokenized
  loopback Remote View.
- Normal semantic click, type, scroll, navigation, history, reload, workflow,
  target, and recovery actions automatically carry the visible revision.
- Glass Agent gains direct conversation, managed Pi readiness/setup, session
  controls, browser context, and frozen one-use mutation confirmation.
- The desktop is organized around Agent, Code, App, Terminal, Tasks, Git,
  Debug, and contextual More. The phone shell exposes Agent, Code, App, Tasks,
  and More directly at narrow terminal sizes.
- Daemon long work has stable operation IDs, bounded events, cancel/reconcile,
  and reconnect-safe inspection. Owned Agent workers are always joined.
- Task verification is inferred from the project unless the user explicitly
  chooses `Settled`; Agent completion alone no longer proves success.

## Breaking changes

There are no intentionally breaking Rust, MCP, workspace-storage, profile, or
CLI removals. The Development TUI information architecture and daemon long-work
protocol changed behavior: scripts should consume stable operation IDs instead
of inferring mutation outcomes from a fixed client timeout.

## Security

Semantic actions carry the visible browser revision and stale targets fail
closed. Human takeover suspends Glass mutation ownership until reconciliation.
Remote View remains loopback-only, random-token protected, bounded, newest-frame
only, revision checked, and explicitly revocable. Pi setup is explicit and no
credentials or provider secrets are logged.

## Installation and migration

The package boundary in this historical release was one-way: `glass-dev`
depended on the exact `glass-browser 0.3.6`. Current users should install the
matching 0.3.12 packages and read [the current migration
guide](../migration/0.3.12.md).

## Known limitations

- Chrome/Chromium remains the only automation backend.
- Structured observation is portable; native browser, graphics, PTY, and
  debugger certification remains platform-specific.
- Remote View is deliberately loopback-only; remote clients use SSH forwarding.

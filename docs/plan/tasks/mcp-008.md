# Bound and negotiate MCP transport

## Objective

Make MCP framing resistant to malformed or oversized input, negotiate supported
protocol versions, and propagate cancellation without increasing idle memory.

## Context

- `docs/architecture/automation.md`
- `docs/mcp.md`

## Path

- `src/mcp/`
- `src/browser/cdp.rs`
- `tests/`
- `docs/mcp.md`
- `docs/architecture/automation.md`

## Requirements

- Bound header, newline frame, content frame, response, and concurrent request
  sizes.
- Strictly validate framing and UTF-8 without lossy protocol conversion.
- Negotiate supported MCP versions and reject incompatible initialization.
- Support request cancellation for waits and pending operations.
- Keep secret-bearing metadata out of logs and error data.

## Verification

- Unit/property tests for framing boundaries and protocol negotiation.
- Fuzz corpus for truncation, huge lengths, malformed headers, and invalid JSON.
- Real client initialize/list/call/cancel integration.
- Idle/default RSS and binary deltas remain within the scorecard.

## Completion

- Newline and content-length framing now enforce explicit header, body, UTF-8,
  timeout, and response bounds before large allocation or output.
- Initialization negotiates the supported MCP protocol version and rejects
  missing or incompatible versions without echoing the supplied value.
- The stdio loop accepts a bounded number of concurrent requests, keeps browser
  operations serialized, and processes cancellation notifications while a
  tool call is pending.
- Dropping a cancelled CDP request removes its response sender from the actor's
  pending map; late Chrome responses are ignored without retaining payloads.
- Logs remain metadata-only, cancellation reasons are ignored, duplicate
  active request IDs are rejected atomically, and bounded generic tool errors
  contain no targets, selectors, evaluated source, typed text, or page errors.
- Added framing boundary tests, a malformed/truncated/invalid-UTF-8 regression
  corpus, deterministic truncation/length/byte property sweeps, output-bound
  tests, lifecycle/notification/duplicate-ID/cancellation tests, and a real
  MCP/Chrome cancellation-and-recovery integration test.
- On the recorded Linux/aarch64 host, the stripped release binary is 4,464,528
  bytes (+65,536 from the `quality-007` baseline), initialized browser-free MCP
  RSS is 4,431,872 bytes, and the three-iteration default workflow peaks at
  6,012,928 bytes Glass RSS. All remain inside the ratified 8 MiB binary, 8 MiB
  idle, and 16 MiB workflow gates.
- A 100-request warm `ping` run over newline-framed stdio measured 0.0794 ms p50
  and 0.1072 ms p95 round-trip latency (0.8941 ms maximum). Requests were 42-43
  bytes and responses were 38-39 bytes, including the newline delimiter.
  Process RSS is the available host-level peak measurement; allocator-level
  peak instrumentation is not available in the release profile, so the
  workflow peak above is the conservative recorded memory bound.
